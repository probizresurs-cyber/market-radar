# Продукт «SEO + GEO» (/seo-geo): что есть, чем стать, как встроить GEO-агента

*4 сентября 2026. Опирается на `06-competitors-geo-market.md` (рынок), `04-geo-agent-purpose.md` (агент) и `05-geo-promotion-plan.md` (план). Здесь — про продукт и код.*

## 1. Что /seo-geo представляет собой сегодня

Продукт `seo-geo` в `src/lib/products.ts` — это раздел «Статьи (SEO + GEO)» (`SEOArticlesView`, 2 100 строк): генерация статей под платформы (сайт, Дзен, vc.ru, Хабр, TenChat…) в двух режимах — SEO и GEO (режим лишь добавляет правила письма из `geo-rules.ts`), библиотека статей, кластер ключей, расширение семантики, «Что спрашивают» (PAA/автокомплит), тех-аудит страницы. Фича-флаг `seo-articles`.

Рядом, но не внутри продукта: «AI Видимость» в core (`AIVisibilityView`, 1 800 строк — опрос LLM по 8 промптам, readiness-чек сайта, рекомендации), проверка позиций Яндекс/Google живым браузером (`check-positions`), Keys.so/Bukvarix, и с этой недели — GEO-агент (`src/lib/geo-agent`, API `/api/geo-agent/audit`, агент `geo-agent`, и вкладка «GEO-аудит сайта» внутри /seo-geo).

Диагноз: продукт называется «SEO + GEO», но GEO в нём — это галочка при генерации статьи. Всё, что делает GEO GEO, — измерение видимости, план, площадки — живёт в других разделах или только в API. Пользователь не видит петли «проверил → сделал → перепроверил».

## 2. Чем должен стать: петля, а не набор инструментов

Один экран-маршрут из пяти шагов; каждый шаг уже частично реализован — задача не написать заново, а соединить.

| Шаг | Что делает пользователь | Что уже есть в коде | Что добавить |
|---|---|---|---|
| **1. Аудит** | Вводит сайт и нишу, получает скор по пяти опорам, план, ответы ассистентов, площадки | `GeoAuditView` → `/api/geo-agent/audit` (сделано 4.09) | сохранять отчёты в `user_data` (сейчас localStorage) для истории «было/стало» |
| **2. Промпт-банк** | Фиксирует 20–50 вопросов клиентов, по которым меряем; видит, где нас нет | `visibility.prompts` + `unansweredPrompts` из отчёта; `SEOKeywordsView`, `keyword-expand`, `paa` | вкладка «Промпты»: список с интентами, флаг «названы / не названы», ручное добавление; это же — набор для агента `geo-agent` (`params.prompts`) |
| **3. Контент под пробелы** | Пишет то, чего не хватает: сравнительную страницу, FAQ, answer-first абзацы | `SEONewArticleView` (тип `comparison`, `faq` уже есть), `geo-rules.ts`, артефакты `faq`/`capsules` из отчёта | кнопка «Написать статью под этот промпт» из промпт-банка → предзаполненный бриф в GEO-режиме; тип статьи по умолчанию — сравнение или FAQ; артефакты агента как черновик |
| **4. Размещения** | Публикует там, откуда ассистенты уже берут мнение о нише | `placementTargets` (домены из ответов) + `SEO_PLATFORMS` (vc, Хабр, Дзен, TenChat…) в `seo-types.ts` | связать: домен из ответа → платформа генерации → статья под её лимиты; чек-лист профилей (Яндекс Бизнес, 2ГИС, Wikidata, YouTube) с отметкой «сделано» |
| **5. Мониторинг и отчёт** | Раз в месяц видит динамику: скор, доля ответов с брендом, цитирование, кто вместо нас | агент `geo-agent` (ежемесячно, TG-алерт), `ai-visibility-monitor`, `check-positions`, `agent_runs` | вкладка «Динамика»: график по прогонам агента; экспорт «отчёт клиенту» (PDF/страница) — тот же формат, что в `05-geo-promotion-plan.md` |

Правило продукта: GEO-статья пишется только под конкретный незакрытый промпт, а не «на тему». Это снимает главную претензию к рынку — «контент ради контента» — и делает результат измеримым.

## 3. Три входа в продукт (воронка)

1. **Бесплатный чекер** на /neyroseti — сейчас три проверки без LLM. Добавить один живой вопрос ассистенту («какие компании по [ниша] посоветуешь») с показом ответа и скор 0–100 по формуле агента. Без регистрации, до 2 минут. Это единственный формат, которого нет у агентств (см. 06 §4), и он уже наполовину написан (`mini-check.ts` + `llm-probe.ts`).
2. **GEO-аудит** в личном кабинете (вкладка, сделана) — для зарегистрированных; результат — план и артефакты. Цена как самостоятельная услуга или в составе продвижения.
3. **Продвижение** — услуга по четырём слоям с ежемесячным отчётом из вкладки «Динамика».

## 4. Единица продажи и тарифы (предложение)

Из рынка (06 §3): вилка 25–400 тыс. ₽/мес без единицы; дыра между 99 ₽ и 19 900 ₽ в мониторинге.

- **Мониторинг** — «промпт × модель × прогон», как у Keys.so и Rush Analytics: например 30 промптов × 3 модели × 1 прогон в месяц = 90 проверок. Тариф на один бренд 2 900–4 900 ₽/мес — в дыру между Pixel Tools и Brandfound. Режим «с веб-поиском / без» показывать явно.
- **GEO-аудит** — разовый, с отчётом и артефактами (ориентир рынка: Trigub 15 000, Rush 150 000).
- **GEO-слой к продвижению** — +N ₽/мес к ведению (формат Trigub/Demis), понятный среднему бизнесу; полный пакет по четырём слоям — от 25 000 ₽/мес по текущему КП.
- Что не продавать: гарантии, «за 30 дней», эксклюзив на нишу.

## 5. Что встроить в код — по приоритету

**Сделано 4.09:** вкладка «GEO-аудит сайта» (`src/components/views/GeoAuditView.tsx`, nav `seo-geo-audit`, иконка Radar), API, агент, CLI.

**Неделя 1–2 (малые правки, большой эффект):**
- Отчёты аудита — в `user_data` через существующий `syncToServer` (ключ `mr_geo_audit_<domain>`), чтобы история не терялась между устройствами; список прошлых прогонов в вкладке.
- Вкладка «Промпты»: из `visibility.prompts`/`unansweredPrompts` + ручной ввод; сохранять в `agent_configs.params.prompts` для `geo-agent`, чтобы месячный замер шёл по тому же набору.
- Кнопка «Написать под промпт» → `SEONewArticleView` с `articleMode: "geo"`, типом `comparison`/`faq` и темой из промпта. Нужен небольшой проп-мостик в `SEOArticlesView`.
- Чекер на /neyroseti: одна проба `probeVisibility` с 1–2 промптами по Gemini/ChatGPT; лимит по IP; показ ответа дословно.

**Месяц 1:**
- Вкладка «Динамика»: чтение `agent_runs` агента `geo-agent` (там лежит весь `GeoReport`), график скора и mention rate по месяцам, дельта по опорам.
- «Отчёт клиенту»: страница-шер (по образцу `presentation-share`/`kp-share`) с итогами месяца — скор было/стало, доля ответов, кто вместо нас, что сделано.
- Чек-лист размещений с отметками (Яндекс Бизнес, 2ГИС, Wikidata, YouTube, vc.ru, Хабр) — хранить в `user_data`.
- Несколько прогонов на промпт (3) с усреднением — иначе месячные дельты шумят; лимит стоимости в тарифе.

**Месяц 2–3:**
- «Правда о бренде»: отдельный набор промптов «что ты знаешь о компании X» → сравнение ответа с фактами сайта (цены, адрес, услуги) → список расхождений. Этого не продаёт никто (06 §3); у нас есть `direct-mentions` и `brand-facts-extract` как база.
- Импорт отчёта Яндекс Вебмастера «Видимость в Алисе AI» и сегмент AI-трафика из Метрики (`ya.ru/neurum`, `chatgpt.com`, `perplexity.ai`) — единственные официальные внешние метрики.
- Ключи Perplexity и YandexGPT на проде — без них два движка в замере «н/д».

## 6. Что переименовать и убрать

- Раздел «Статьи (SEO + GEO)» → «SEO + GEO»; порядок вкладок: GEO-аудит → Промпты → Статьи (новая / библиотека) → Кластер ключей → Что спрашивают → Размещения → Динамика.
- «AI Видимость» из core — либо перенести в этот продукт как «Динамика», либо оставить в core как лёгкий еженедельный опрос (он уже есть в `ai-visibility-monitor`); держать два разных экрана с одной функцией не стоит.
- В генераторе статей режим GEO должен предлагать типы «сравнение» и «FAQ» первыми и требовать промпт-источник.

## 7. Риски и ограничения

- Ответы ассистентов недетерминированы — один прогон не показатель; в UI это уже написано, в тарифе должно быть заложено 3 прогона.
- Bing проверяется скрейпингом и иногда отдаёт урезанную выдачу — для продакшена подключить Bing Webmaster Tools клиента.
- Стоимость: полный аудит с опросом трёх ассистентов — десятки вызовов LLM; лимитировать через `checkAiAccess` и тариф.
- Локально UI не проверить с логином (нет БД) — проверка на проде после деплоя.
