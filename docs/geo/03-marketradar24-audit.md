# GEO-аудит marketradar24.ru — первый прогон

*Дата: 3 сентября 2026. Прогон: `npx tsx scripts/geo-audit-cli.ts https://marketradar24.ru`. 6–14 страниц (главная, /geo, /blog, /pricing, /neyroseti, /competitors, /partners + ссылки из llms.txt), опрос ChatGPT / ChatGPT Search / Gemini (реальные вызовы; OpenAI-ключ в окружении оказался без кредитов — см. ограничения ниже).*

## Итоговый скор: 54/100

| Опора | Скор | Комментарий |
|---|---|---|
| Доступность для краулеров | 93/100 | Сильная сторона — почти всё сделано правильно |
| Извлекаемость контента | 35/100 | Главная слабость |
| Сущность и доверие | 80/100 | Хорошо, есть пробелы |
| Свежесть | 53/100 | Средне |
| Внешние сигналы | 15/100 | Совсем не тронуто |

## Что уже сделано хорошо

- **robots.txt открыт всем ключевым краулерам**: OAI-SearchBot, ChatGPT-User, GPTBot, PerplexityBot, ClaudeBot, Google-Extended, Googlebot, Bingbot, YandexBot — все `allowed`. Это редкость: по данным Otterly у 73% сайтов есть технические барьеры для AI-краулеров.
- **Есть llms.txt и llms-full.txt**, оба валидные, 23 рабочие ссылки, ни одной битой.
- **Сайт есть в индексе Bing** (~50 страниц) — это retrieval-слой ChatGPT Search и Copilot.
- **Organization JSON-LD, FAQPage, автор на статьях, уникальные title** — сущность размечена лучше, чем у большинства.

## Главная проблема: контент не написан для извлечения ответа

Это не техническая проблема — сайт открыт, размечен, индексируется. Проблема в том, *как написан текст*:

- **0% страниц начинаются с прямого ответа.** Лид главной — маркетинговый крючок («Пока вы читаете это — конкуренты анализируют ваш рынок»), а не определение. По исследованию Kevin Indig (1,2 млн ответов ChatGPT), 44% цитат берутся именно из первых 30% страницы, и цитируемые абзацы в 2 раза чаще имеют форму «X — это…».
- **Только 1% подзаголовков сформулированы как вопрос.** Ассистент ищет заголовок, совпадающий с запросом пользователя — «Сколько стоит…», «Как выбрать…».
- **Ни одной сравнительной страницы** («MarketRadar vs Keys.so», «альтернативы SpyWords»). По данным Semrush/Indig сравнительный контент даёт в 2,4 раза больше упоминаний бренда в ответах, чем информационный — и именно на такие страницы чаще выходят с рекомендательными запросами вроде «посоветуй сервис для X».
- **Мало ссылок на внешние источники** (7% страниц) — цитаты с атрибуцией дают +43% видимости в контролируемом эксперименте (Aggarwal et al., KDD 2024), у нас почти нет.

## Реквизиты почти не видны

На проверенных страницах нашли только email в разметке — нет видимых в HTML ИНН/ОГРН, юрлица, адреса, телефона (они наверняка есть на странице оферты, но её не было в выборке — стоит добавить `/rekvizity` или `/o-kompanii` в приоритетную навигацию и в sitemap с высоким priority). Для Алисы и GigaChat проверяемый юрстатус — фильтр доверия.

## Внешние сигналы — пока пусто

`sameAs` в Organization содержит только два Telegram-канала. Нет связки с YouTube, Яндекс Бизнесом, 2ГИС, vc.ru/Хабром, Wikidata — а именно упоминания на YouTube сильнее всего коррелируют с видимостью в ChatGPT/AI Mode/AIO (r≈0,74 на выборке 75 000 брендов, Ahrefs).

## Что ответили реальные ассистенты

На 6 промптов («какие компании посоветуешь по аналитике конкурентов», «сравни сервисы», «что ты знаешь о MarketRadar» и т.д.) Gemini назвал бренд в 1 из 6 ответов (17%), ни разу не сославшись на marketradar24.ru как источник. Domains, которые Gemini процитировал вместо нас по этой нише: **vc.ru, kokoc.com, texterra.ru, sostav.ru, pikabu.ru, keys.so** — это и есть готовый список площадок для размещения статей и упоминаний, а не абстрактная рекомендация «работайте с медиа».

*Ограничение:* ChatGPT и ChatGPT Search не ответили — ключ OpenAI в окружении исчерпал кредиты (`insufficient_quota`), это не ошибка агента. Perplexity, Claude и YandexGPT не проверялись — ключи не настроены в `.env.local`. Полная картина потребует ключей ANTHROPIC_API_KEY, PERPLEXITY_API_KEY, YANDEX_GPT_IAM_TOKEN/YANDEX_GPT_FOLDER_ID и пополненного OPENAI_API_KEY.

## Приоритетный план (агент сгенерировал 15 пунктов, ниже — первая треть)

1. **Контент есть в HTML без JS** — /pricing почти без текста в сыром HTML (116 слов) — вероятно, рендерится клиентским JS уже после первой отрисовки.
2. **Sitemap.xml** — 6 URL с якорями (`/#faq`, `/#geo`) отдают краулеру ту же главную; убрать их из sitemap.
3. **Answer-first абзацы** под H1 и под каждым H2 — 40–70 слов, формат «X — это…», без ссылок внутри.
4. **Вопросительные H2/H3** вместо «Возможности платформы» → «Что умеет MarketRadar».
5. **Таблицы сравнения** — сейчас всего 5 на весь сайт.
6–7. Сравнительные страницы + ссылки на внешние источники.
8–9. Реквизиты в HTML + отдельная страница «О компании».
10. Видимая дата «Обновлено: …» — сейчас видна только на 36% страниц.

Полный план с howTo, effort и затронутыми URL — в JSON-отчёте агента (см. `GeoReport.plan`).

## Готовые артефакты, которые агент сгенерировал автоматически

- **llms.txt** — обновлённая версия с реальными заголовками страниц (детерминированно, без LLM).
- **robots-блок** со всеми 16 краулерами ассистентов, сгруппированными по названию.
- **Organization JSON-LD** с объединённым `sameAs` (текущая разметка + найденные ссылки на соцсети).
- **6 FAQ-черновиков** — по одному на каждый промпт, где ни один ассистент не связал вопрос с брендом.
- **6 answer-капсул** — шаблоны прямого ответа для страниц с самым слабым лидом.
- **Список площадок для размещений** — из реального ответа Gemini (vc.ru, kokoc.com, texterra.ru, sostav.ru и др.), без выдумывания.

Без `ANTHROPIC_API_KEY` FAQ и капсулы — это шаблоны-заготовки с плейсхолдерами; агент явно помечает это в `limitations`, а не выдаёт черновик за готовый текст.

## Что это доказывает про самого агента

- Обход глазами реального краулера (парность браузер/GPTBot, статус-коды, JS-зависимость) — работает.
- Разбор robots.txt по 16 ботам, llms.txt (включая проверку битых ссылок), sitemap (включая обнаружение якорных URL и «одинаковых lastmod») — работает.
- Индексация в Bing без ключа — работает.
- Реальный опрос ассистентов с извлечением цитируемых доменов (включая разбор редиректов Gemini grounding через поле `title`) — работает и дал конкретные, проверяемые названия площадок, а не общие советы.
- Скоринг честно показывает «н/д», когда данных нет (ключа нет, LLM не ответил) — вместо того чтобы выдавать 0% за реальный провал.
