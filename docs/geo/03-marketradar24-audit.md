## Исправление: два бага в самом агенте искажали оценку

При подготовке кейс-стади для блога тот же инструмент оценил заведомо хорошо написанный текст лишь в 65/100 — подозрительно низко. Нашлись причины:

1. **`\b` не видит кириллицу.** В JavaScript граница слова `\b` определена только через ASCII-буквы, цифры и `_`. Русское слово рядом с пробелом (то есть почти всегда) не даёт границы ни до, ни после себя — проверки на `\b` для «это/является» (answer-first лид), «как/что/почему» (вопросительные заголовки) и «ИНН/ОГРН/автор» (реквизиты) массово не срабатывали на русском тексте.
2. **H1 вырезался вместе с `<header>`.** Разбор страницы удалял тег `<header>` до того, как считывал `<h1>` — а на этом сайте заголовок статьи лежит именно в семантическом `<header>`. Агент писал «нет H1» там, где H1 был.

Оба бага исправлены в `src/lib/geo-agent/html.ts` (замена `\b` на явные проверки границы по алфавиту рус+лат+цифры; H1 теперь считывается до удаления `<header>`). Заодно поправлен парсинг числа результатов Bing (`external.ts`): один прогон показал «63 160 700 страниц в Bing» — регулярка цепляла счётчик расширенного веб-поиска вместо `site:`-фильтра; теперь число используется только в правдоподобном диапазоне, а нижней границей всегда служит количество реально найденных ссылок на домен.

После исправлений оценка кейс-стади поднялась с 65 до 100 из 100 без единой правки текста — проверка наконец увидела то, что в тексте было с самого начала. Дальше — пересчитанные цифры по marketradar24.ru.

## Что реально требует работы

- **Только 20% страниц начинаются с прямого ответа.** Лид главной — маркетинговый крючок («Пока вы читаете это — конкуренты анализируют ваш рынок»), а не определение. По разбору 1,2 млн ответов ChatGPT (Kevin Indig), 44% цитат берутся из первых 30% страницы, и модель вдвое чаще выбирает абзацы в форме «X — это…».
- **Ни одной сравнительной страницы** («MarketRadar vs Keys.so», «альтернативы SpyWords») — по данным Semrush/Indig такой контент даёт в 2,4 раза больше упоминаний бренда в ответах ассистентов, чем информационный.
- **Мало ссылок на внешние источники** (10% страниц) — цитаты с атрибуцией дают +29–43% видимости в контролируемом эксперименте (Aggarwal et al., KDD 2024).
- **Нет отдельной страницы «О компании»** в приоритетной навигации/sitemap — реквизиты есть, но не собраны в одном месте, которое легко процитировать целиком.
- **/pricing почти без текста в сыром HTML** (116 слов) — похоже на контент, дорисовываемый клиентским JS уже после первой отрисовки; краулеры ассистентов JS не выполняют (Vercel/MERJ).
- **Дата обновления видна лишь на 20% страниц.**
- **`sameAs` содержит только два Telegram-канала** — нет связки с YouTube, Яндекс Бизнесом, 2ГИС, vc.ru/Хабром, Wikidata, хотя именно упоминания на YouTube сильнее всего коррелируют с видимостью в ChatGPT/AI Mode/AIO (r≈0,74 на выборке 75 000 брендов, Ahrefs).
- **6 URL в sitemap с якорями** (`/#faq`, `/#geo`) — краулер получает по ним ту же главную страницу.

## Что ответили реальные ассистенты

На пять проверочных промптов Gemini назвал бренд в одном ответе (20%) и ни разу не сослался на marketradar24.ru как на источник. Домены, которые Gemini процитировал вместо нас по этой нише: **kokoc.com, click.ru, dtf.ru, vc.ru, workspace.ru, sostav.ru, pricer24.com, tenchat.ru, lpgenerator.ru, pikabu.ru** и ещё несколько — это готовый список площадок для размещения статей и упоминаний, а не абстрактная рекомендация «работайте с медиа».

*Ограничение:* ChatGPT и ChatGPT Search не ответили — ключ OpenAI в окружении исчерпал кредиты (`insufficient_quota`), это не ошибка агента. Perplexity, Claude и YandexGPT не проверялись — ключи не настроены в `.env.local`. Полная картина потребует ANTHROPIC_API_KEY, PERPLEXITY_API_KEY, YANDEX_GPT_IAM_TOKEN/YANDEX_GPT_FOLDER_ID и пополненного OPENAI_API_KEY. Bing-проверка тоже нестабильна между прогонами одной сессии (то видит результаты, то нет при одинаковом запросе) — известное ограничение скрейпинга без официального API, для продакшена надёжнее подключить Bing Webmaster Tools.

## Приоритетный план (15 пунктов, первая половина)

1. Answer-first абзацы под H1 и под каждым H2 — 40–70 слов, формат «X — это…», без ссылок внутри.
2. Хотя бы одна сравнительная страница на каждого ключевого конкурента.
3. Разобраться, почему /pricing почти пуст в сыром HTML.
4. Убрать 6 якорных URL из sitemap.
5. Больше ссылок на внешние источники в статьях.
6. Собрать реквизиты и факты о компании на одной странице «О компании».
7. Видимая дата «Обновлено: …» на каждой значимой странице.
8. Связать `sameAs` с YouTube, Яндекс Бизнесом, 2ГИС, vc.ru/Хабром.

Полный план с howTo, effort и затронутыми URL — в JSON-отчёте агента (`GeoReport.plan`).

## Что это доказывает про сам инструмент

- Разбор HTML — общий код для любого сайта, поэтому баг искажал оценку каждого русскоязычного сайта одинаково, включая собственный. Нашли его не на абстрактном тесте, а сравнив ожидаемо высокий результат нового текста с тем, что показал инструмент — расхождение и стало сигналом.
- После исправления оценка одной и той же статьи выросла с 65 до 100 без единой правки текста — правильно откалиброванный инструмент измеряет содержание, а не артефакт собственного парсинга.
- Реальный опрос ассистентов с извлечением цитируемых доменов — работает и дал конкретные, проверяемые названия площадок.
- Скоринг честно показывает «н/д», когда данных нет (ключа нет, LLM не ответил, Bing не ответил), вместо того чтобы выдавать ложный ноль.
