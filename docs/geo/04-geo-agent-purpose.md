# GEO-агент: в чём его смысл

*Документ для команды и для продуктовых текстов. Что это, зачем, что он делает и чего не делает. Код — `src/lib/geo-agent/`, обоснование — `01-research-techniques.md`, `02-research-tools-market.md`.*

## Одним абзацем

GEO-агент — это инструмент, который отвечает на один вопрос владельца сайта: «когда клиент спрашивает ChatGPT, Алису или Gemini, кого посоветовать, — почему называют не меня и что с этим делать». Он смотрит на сайт глазами краулера ассистента, задаёт реальным ассистентам реальные вопросы клиентов, фиксирует, кого они называют и цитируют вместо нас, и превращает всё это в приоритизированный план с готовыми артефактами. Один и тот же код гоняет и marketradar24.ru, и сайт любого клиента.

## Какую проблему решает

Поиск перестал быть единственным входом. Клиент всё чаще задаёт вопрос ассистенту и получает не десять ссылок, а один абзац с двумя-тремя названиями. Если бренда там нет — этот клиент не узнает о существовании компании, и никакая позиция в Яндексе этого не компенсирует: по данным Ahrefs только 12% страниц, которые цитируют ассистенты, стоят в топ-10 Google по тому же запросу.

При этом рынок продаёт GEO как магию: «гарантируем попадание в ответ», «за две недели», «знаем алгоритм». Ничего из этого невыполнимо — ответ собирает модель, алгоритм не публикуется, а результат копится месяцами. Агент нужен ровно для того, чтобы заменить обещания измерением: вот что ассистенты отвечают сегодня, вот что мешает вам туда попасть, вот что делать первым, вот как это проверить через месяц.

## Что он измеряет

Пять опор, каждая — с проверками и весом, обоснованным исследованиями, а не вкусом:

1. **Доступность** — пускает ли robots.txt краулеров ответов (OAI-SearchBot, PerplexityBot, Claude-SearchBot и ещё 13), отдаёт ли сайт боту то же, что браузеру, есть ли контент в HTML без JavaScript (краулеры OpenAI/Anthropic/Perplexity JS не выполняют), есть ли сайт в индексе Bing — retrieval-слое ChatGPT Search.
2. **Извлекаемость** — отвечает ли первый абзац прямо (44% цитат ChatGPT берутся из первой трети страницы), сформулированы ли заголовки как вопросы, есть ли таблицы, факты с единицами, ссылки на источники, сравнительные страницы (они дают в 2,4 раза больше упоминаний бренда).
3. **Сущность и доверие** — размечена ли компания как Organization с sameAs, видны ли реквизиты, автор, есть ли страница «О компании».
4. **Свежесть** — видимая дата обновления, реальные lastmod, обновлялся ли контент за 90 дней.
5. **Внешние сигналы** — называют ли ассистенты бренд, цитируют ли сайт, кого цитируют вместо него, доминируют ли конкуренты, есть ли связка с YouTube, картами, медиа.

Итог — скор 0–100 и скор по каждой опоре. Не для красоты: скор нужен, чтобы через месяц сравнить «было/стало» по одному и тому же набору проверок и промптов.

## Что он выдаёт

- **Приоритизированный план**: провалившиеся проверки, отсортированные так, чтобы сначала чинить то, без чего остальное не работает (доступность → извлекаемость → сущность → свежесть → внешние сигналы), с оценкой усилий и затронутыми URL.
- **Артефакты для вставки**: llms.txt по реальным страницам, robots-блок для 16 ботов, Organization/FAQPage JSON-LD, черновики FAQ под промпты, где нас никто не назвал, answer-капсулы для страниц со слабым первым абзацем.
- **Список площадок для размещения** — не «работайте с медиа», а конкретные домены, которые ассистент процитировал по нашей нише вместо нас (в прогоне по marketradar24.ru: vc.ru, kokoc.com, texterra.ru, sostav.ru, pikabu.ru, keys.so).
- **Полный текст каждого ответа ассистента** — evidence trail «промпт → ответ → источники», чтобы любую цифру отчёта можно было проверить руками.

## Как он встроен в продукт

- **Для нас** — раз в месяц гоняет marketradar24.ru, сравнивает скор с прошлым, шлёт алерт в Telegram при падении на 10+ баллов. Это наш собственный контроль качества: мы продаём GEO, значит должны первыми видеть, когда у нас самих просело.
- **Для клиентов** — тот же вход (адрес, ниша, конкуренты) через `POST /api/geo-agent/audit`, агент `geo-agent` в Agent Hub по расписанию, CLI для разового прогона. Отчёт агента — сырьё для КП и для ежемесячного отчёта по продвижению: «вот скор в начале, вот через месяц, вот что сделано».
- **Как часть воронки** — бесплатная диагностика на /neyroseti показывает три проверки; полный GEO-аудит — следующая ступень перед продвижением.

## Принципы, из-за которых он отличается от трекеров

- **Честные промпты.** Ассистентам задаются вопросы так, как их задаёт человек, без подсказок «если знаешь бренд X». Иначе метрика обманывает сама себя.
- **«Нет данных» ≠ ноль.** Нет ключа, ассистент не ответил, Bing не отдал выдачу — проверка помечается «н/д» и не портит скор. Ноль ставится только за реальный провал.
- **Только проверяемое.** Артефакты строятся из того, что реально нашлось на сайте; Claude лишь дописывает текст черновиков и не имеет права придумывать цифры.
- **Гигиена не выдаётся за рычаг.** llms.txt и Schema.org в скоре весят мало — измеримого прироста цитирований у них нет (Google, SE Ranking на 300 тыс. доменов, Ahrefs на 137 тыс. сайтов). Вес — у структуры контента, индексации в Bing/Яндексе и внешних упоминаний.

## Чего он не делает и не обещает

- Не гарантирует попадание в ответ: ответ собирает модель, и одну и ту же фразу она отвечает по-разному двум людям подряд.
- Не заменяет контент-работу и размещения: он говорит, что и где менять, но абзацы, сравнительные страницы и публикации кто-то должен написать.
- Не измеряет точно за один прогон: ответы недетерминированы, честная картина — несколько прогонов и динамика по месяцам.
- Не покрывает движки без ключа: Perplexity и YandexGPT нужны свои ключи; Bing проверяется скрейпингом и иногда отдаёт урезанную выдачу — для продакшена надёжнее Bing Webmaster Tools.

## Что дальше

- Вкладка отчёта в личном кабинете (сейчас — Agent Hub, API, CLI).
- Несколько прогонов на промпт с доверительным интервалом (как у geobench/Evertune).
- Проверка «Integrity» — что ассистенты рассказывают о бренде и где врут (цены, услуги, адрес).
- Импорт отчёта Яндекс Вебмастера «Видимость в Алисе AI» и сегмента AI-трафика из Метрики.
- Единица тарификации «промпт × модель × прогон», как у Keys.so и Rush Analytics, с явным режимом «с веб-поиском / без».
