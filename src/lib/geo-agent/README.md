# GEO-агент

Полный аудит видимости сайта в ответах ассистентов (GEO — Generative Engine
Optimization) и приоритизированный план + готовые артефакты. Спроектирован
как переиспользуемый модуль: один и тот же код гоняет наш собственный сайт
и любой сайт клиента — вход везде один и тот же `GeoAuditInput`.

Обоснование каждого веса и приоритета — в `docs/geo/01-research-techniques.md`
(что доказано исследованиями) и `docs/geo/02-research-tools-market.md`
(что делают существующие инструменты рынка).

## Файлы

- `types.ts` — все типы отчёта.
- `discovery.ts` — разбор robots.txt (16 ботов-ассистентов), llms.txt, sitemap.xml.
- `html.ts` — разбор одной страницы: answer-first лид, вопросительные заголовки,
  факты, FAQ, реквизиты, JSON-LD.
- `crawl.ts` — обход сайта: браузерный UA + отдельный заход под GPTBot
  (ловит клоакинг/бот-щиты), выбор страниц из sitemap + llms.txt.
- `external.ts` — проверка индексации в Bing без ключа, классификация доменов
  (медиа/отзовик/UGC/каталог) для площадок размещения.
- `llm-probe.ts` — честный опрос ChatGPT / ChatGPT Search / Perplexity /
  Gemini / Claude / YandexGPT (только по доступным ключам), извлечение
  цитируемых доменов и названных брендов.
- `checks.ts` — 27 проверок по пяти опорам (access/extract/entity/freshness/
  external) и скоринг.
- `plan.ts` — превращает провалившиеся проверки в приоритизированный план.
- `artifacts.ts` — llms.txt, robots-блок, Organization JSON-LD, FAQPage
  JSON-LD, FAQ-черновики, answer-капсулы, список площадок — всё детерминированно,
  работает без ANTHROPIC_API_KEY.
- `run.ts` — точка входа `runGeoAudit(input, onProgress?)`; если есть
  ANTHROPIC_API_KEY, просит Claude улучшить FAQ/капсулы текстом (с явным
  запретом придумывать цифры), иначе оставляет шаблоны и говорит об этом
  в `limitations`.

## Использование

Как библиотека:

```ts
import { runGeoAudit } from "@/lib/geo-agent/run";

const report = await runGeoAudit({
  websiteUrl: "https://example.ru",
  brandName: "Пример",     // опц, иначе угадывается из <title>
  niche: "услуги ремонта",  // опц, но сильно улучшает промпты для опроса ассистентов
  maxPages: 15,
});
```

Как API: `POST /api/geo-agent/audit` (требует авторизации, как остальные
`/api/ai-visibility/*`).

Как агент платформы: `geo-agent` в `src/lib/agents/registry.ts` — раз в месяц
гоняет полный аудит для `last_analyzed_company` пользователя, сравнивает скор
с прошлым прогоном, алертит в Telegram при падении ≥10 баллов.

Как CLI (для разработки/разовой проверки, без БД и без сервера):

```bash
npx tsx --env-file=.env.local scripts/geo-audit-cli.ts https://example.ru \
  --niche="ваша ниша" --max-pages=15 --out=report.json
```

Флаги: `--no-visibility` (только технический аудит, без опроса ассистентов),
`--brand=`, `--niche=`, `--out=`.

## Честность вместо красивых цифр

- Проверка, для которой нет данных (ключа нет, LLM не ответил, Bing не
  ответил), помечается статусом `na` и не портит и не подделывает скор —
  опора считается только по доступным проверкам.
- Опрос ассистентов идёт чистыми промптами, без подсказок про бренд (как
  реальный пользователь) — иначе метрика мониторинга сама себя обманывает.
- Артефакты — черновики. FAQ и answer-капсулы без ключа Claude — шаблоны с
  плейсхолдерами `[уточните: ...]`, а не выдуманный текст.
- Список площадок для размещения строится только из реальных ответов
  ассистентов (`citedDomains`), а не из общего списка «попробуйте vc.ru,
  Хабр, YouTube».
